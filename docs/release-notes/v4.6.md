## 中文

### 🛠 修掉「DeleteFile failed; code 5」

**Windows 不允許覆蓋正在執行中的程式。** 你裝 v4.5 的時候 LagScope 還開著,
所以安裝程式走到一半才發現檔案動不了,然後丟出一個完全看不懂在講什麼的錯誤,
還讓你在「重試 / 跳過這個檔案 / 取消安裝」裡面選——這三個選項沒有一個告訴你該做什麼。

原本安裝檔是有設 `CloseApplications=yes` 的,理論上會自己把程式關掉。但 LagScope 是
**托盤程式,沒有可見視窗**,Windows 的 Restart Manager 對這種程式常常關不掉。

現在改成:程式一啟動就佔住一個具名 mutex,安裝檔用 `AppMutex` 去檢查它——
**在動任何檔案之前**就發現程式還開著,然後好好跟你講「請先關掉 LagScope」,並提供重試。
這個 mutex 存在的唯一目的就是給安裝程式看,程式自己完全不讀它。

### 🇹🇼 安裝畫面終於有中文了(而且是繁體)

這件事其實一直是壞的,而且是**安靜地**壞。原本的寫法是「編譯器有中文語言檔就用,沒有就退回英文」:

```
#if FileExists(AddBackslash(CompilerPath) + "Languages\ChineseSimplified.isl")
```

問題是**中文是 Inno Setup 6.5 才收進官方語言包的**,而 CI 機器上那套比較舊——
所以這個檢查每次都找不到,每次都退回英文,**發了八個版本沒人發現**。
這正是我當初加那個檢查想避免的失敗方式,結果它自己就是那樣壞的。

現在語言檔**跟著這個 repo 一起走**,不再去猜編譯器有沒有:

- 新增 **繁體中文**(原本只準備了簡體)
- 簡體、日文、韓文一併帶著
- 萬一哪天語言檔跟編譯器版本不合,CI 會**印出警告**再退回英文版,而不是安靜退回

### 🔄 不用再去 GitHub 手動下載了

托盤選單發現新版時,現在多一個 **「直接更新」**:

```
有新版本 4.7（你在用 4.6）

會下載官方安裝程式（約 44 MB）、核對校驗碼，然後自動裝好。
本程式會先關掉——Windows 不允許覆蓋正在執行的程式——裝完會自己開回來。

[直接更新]  [去下載]  [跳過這個版本]  [以後再說]
```

**這是這個程式裡唯一一個「下載一個檔案然後執行它」的功能,所以規矩訂得很死:**

| 規矩 | 為什麼 |
| --- | --- |
| 只收 **https**,而且主機必須在一份**固定的 GitHub 清單**裡 | 網址是從 API 拿的不是使用者打的,但還是再檢查一次;**跟著重導向之後會再檢查一次**,所以 API 就算回了奇怪的東西也帶不到別的地方去 |
| 下載的**位元組必須符合 API 公布的 sha256**,不符就直接刪掉 | 這是「下載」和「執行」之間唯一的一道關卡 |
| **沒有公布校驗碼就不自動安裝**,只給你連結 | 為了省你一次點擊而去執行一個沒驗證過的執行檔,這個交易不划算 |
| **只有用安裝版裝的才會自我更新** | 免安裝版要自己覆蓋自己正在執行的檔案,做錯了你會連一個能用的程式都不剩。免安裝版維持原本的「開下載頁」 |

新增的 28 個測試裡,**大部分在測「它該拒絕」**:雜湊不符、大小不符、走 http、
長得像 github 的假網域、沒有校驗碼、免安裝版。成功的路徑只有一個測試,該拒絕的路徑有一堆。

順帶一提,做這個功能的時候測試抓到我自己寫的一個 bug:我新增的 `update.failed` 這個字串鍵
**跟已經存在的一個同名**,Python 字典後面蓋掉前面,結果日韓翻譯帶著 `{reason}` 佔位符、
英文版卻沒有。現在多加了一個測試,專門檢查有沒有重複的鍵。

## English

### The "DeleteFile failed; code 5" error

Windows will not replace a running executable. Setup had `CloseApplications`, but a tray app
with no visible window is not reliably closed by Restart Manager, so the wizard got halfway
through and failed with an error that told the person nothing about what to do.

The app now holds a named mutex for its lifetime and the installer declares `AppMutex`, so
Setup notices *before* touching any files and asks for the app to be closed, with a retry.
The mutex exists for that reason alone; nothing in the app reads it.

### A Chinese installer

This was broken the whole time, and silently. Chinese only became a bundled Inno Setup
translation in 6.5, and the "use it if the compiler has it" check found nothing on the CI
runner - every release, for eight releases, invisibly. That is precisely the failure mode the
check was meant to prevent.

The `.isl` files now travel with the repository rather than being looked for. Traditional
Chinese is added alongside Simplified, and if a translation ever fails to compile, CI emits a
warning and falls back to English rather than either failing or degrading in silence.

### It updates itself

The tray offers to install the update: it downloads the official installer, verifies it
against the sha256 the releases API publishes, runs it, and quits so nothing is locked.

This is the one feature that downloads a file and then executes it, so the rules are strict:
https only and the host must be on a fixed GitHub list, re-checked after redirects so the API
cannot point it elsewhere; the bytes must match the published digest or the file is deleted;
no published digest means a link rather than an install, because running an unverified
executable to save a click is not a trade worth making; and only a copy placed by the
installer updates itself, since rewriting the executable a portable copy is running from can
leave someone with no working app at all.

Most of the 28 new tests are about refusing. The happy path is one test.

### Also

- A check that no string key is defined twice, which is how `update.failed` came to mean two
  different things during this change - caught by the placeholder test, not by review.
- 522 tests, green on Windows, macOS and Ubuntu across Python 3.9, 3.11 and 3.12.
