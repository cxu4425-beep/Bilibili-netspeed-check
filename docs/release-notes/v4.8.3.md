## 中文

### 🧹「System Idle Process」不是一個程式

真機報告裡的這一段:

```
25 program(s) hold connections; busiest:
  System Idle Process  (317 connection(s))   ← 排第一
  RobloxPlayerBeta.exe  (25 connection(s))
  chrome.exe  (13 connection(s))
```

**Windows 把「查不到擁有者的連線」歸給 PID 0**,psutil 就把它顯示成 `System Idle Process`。
那多半是 TIME_WAIT 狀態的殘留 socket,**不是一個程式,也沒有東西可以量**。

而這份清單存在的意義正是「挑一個程式來監測」。它有 317 條、穩穩排在第一,
等於清單最顯眼的位置放了一個選不得的東西。現在 PID 0 直接排除掉。

`peers_for()` 也有同一個洞——它會把一條無主的連線算到某個有名字的程式頭上。一起修了。

### 🩺 GUI 的診斷報告不該叫你去開命令列

同一份報告裡:

```
[skip] room info
        no room id - pass one: --selftest 21452505
[skip] play URLs        needs a room id
[skip] live measurement needs a room id
[skip] CDN edges        needs a room id
```

**四個最重要的檢查全跳過了,然後叫使用者去用命令列——而我做這個托盤按鈕的全部目的
就是讓人不用開命令列。** 這不是使用者的問題,是我把功能做了一半。

現在沒有正在監測直播間時,它會直接問你:

```
貼上一個正在直播的房間號或直播間網址。
沒有的話可以留空按確定——但和 B 站有關的四項檢查就會跳過，
而那幾項正是最需要在真實環境驗證的。
```

留空按確定照樣可以跑(只是那四項還是會跳過),按取消就什麼都不做。

## English

### "System Idle Process" is not a program

Windows attributes a connection whose owner it cannot determine to pid 0, which psutil renders
as `System Idle Process`. Those are usually sockets in TIME_WAIT - not a program, and nothing
that can be measured. On the machine that sent the report there were 317 of them, sitting at
the top of a list whose entire purpose is picking a program to monitor. Pid 0 is now excluded,
in `peers_for()` as well, where an unowned socket was being counted against a named program.

### A self-test in the GUI should not name a command-line flag

Four checks - room info, play URLs, the live measurement, the CDN comparison - all skipped for
want of a room id, and the report told the reader to run `--selftest 21452505`. That button
exists precisely so a terminal is never the answer; leaving it half-done was my omission, not
the user's mistake. It now asks for a room id when nothing is being monitored.

### What the report confirmed

The first real-world evidence this project has had. Confirmed working on a real Windows
machine: the installer, the GUI self-test, DNS resolution, **the Bilibili API** (`code=0`),
default gateway detection, ICMP ping, the connection table (it identified the official
Bilibili PC client), history recording and report rendering.

Still unverified, and they are the four that matter most: playurl parsing, the live latency
measurement, the CDN edge comparison, and the hostname decoder. All four need a live room id -
which is what the second fix above is for.
