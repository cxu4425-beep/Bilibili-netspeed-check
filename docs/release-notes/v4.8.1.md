> **修掉「DeleteFile 失敗;代碼 5」——這次用的方法不管你在跑哪個版本都有效。**
> v4.6 的修法有個根本問題:它只對「已經裝了 v4.6 以上」的人有用,而會遇到這個錯誤的人正好都不是。
>
> Fixes the install-over-running error in a way that does not depend on which version is running.

## 中文

### 我上次的修法從根本上就不可能對

v4.6 我加了 `AppMutex`:程式啟動時佔住一個具名 mutex,安裝程式檢查它,發現程式還開著就請你先關掉。

**但 mutex 是 v4.6 才加的。** 所以:

| 你在跑的版本 | 會不會建立 mutex | 安裝程式看不看得到 |
| --- | --- | --- |
| v4.6 以前 | ❌ | ❌ **看不到,照樣爆錯** |
| v4.6 以後 | ✅ | ✅ |

先有雞還是先有蛋:**修正住在程式裡,但程式必須先是修過的版本,安裝程式才偵測得到。**
而會撞到這個錯的人,定義上就是還沒裝到修過的版本的人。**我寫的修正,修不了它自己被寫出來要修的那個情況。**

那第二道防線 `CloseApplications=yes` 為什麼也沒擋住?因為 Restart Manager 是「送一個關閉訊息給程式的
最上層視窗」——**LagScope 是托盤程式,視窗是隱藏的**,那個訊息等於沒送到,等逾時之後安裝程式就
照樣往下走,然後 DeleteFile 失敗。

### 這次的修法不看版本

兩個改動,都跟正在跑的是哪一版無關:

1. **`CloseApplications=force`** — Restart Manager 先好好問,不回應的就直接終止。
2. **安裝前先自己動手關**:在 `PrepareToInstall` 裡先送一次關閉請求(`taskkill /IM`),
   等 0.8 秒,再強制一次(`taskkill /F /IM`)。先禮後兵——自己乖乖結束的程式來得及把歷史紀錄寫完,
   不理會的最多掉當下那一分鐘。

`AppMutex` 留著:v4.6 以上的版本仍然會得到「請先關掉 LagScope」那個比較體面的提示,
而不是被直接砍掉。

### 我沒辦法在這裡測這個

**這點要講清楚:我的開發環境沒有 Windows,也沒有 Inno Setup 編譯器,所以這個安裝程式我
從頭到尾都沒有真的跑過。這已經是第二次修同一個問題了。**

在做不到實測的情況下,我能做的驗證是:把 Inno Setup 的原始碼抓下來,逐項確認我用的東西真的存在——

- `CloseApplications=force`:確認是合法值(`SSDV(ssCloseApplications, ['force', SYes, SNo])`)
- `PrepareToInstall(var NeedsRestart: Boolean): String`:簽名與官方列的完全一致
- `Sleep` / `Exec`:確認都是已註冊的腳本函式(`procedure Sleep(const Milliseconds: Cardinal)`)

另外 CI 只要編得出安裝程式,至少代表那段 Pascal 語法是通的。**但「編得過」不等於「行為對」。**

### 萬一還是不行

托盤右鍵 → 結束 LagScope → 再執行安裝程式。這是一定會過的。

而且**只要成功裝上這一版一次,之後就不會再碰到了**:v4.6 之後的更新走程式內建的「直接更新」,
那條路是程式自己下載、自己啟動安裝程式、然後自己結束——不會有任何東西被鎖住。

## English

### The previous fix could not have worked

v4.6 added `AppMutex`: the app holds a named mutex, Setup checks for it and asks for the app to
be closed. But the mutex only exists from v4.6 onwards, so Setup can only see it on a machine
already running v4.6 or later - and anyone hitting this error is by definition not running one.
The fix lived inside the application, which meant it could not fix the case it was written for.

`CloseApplications=yes` did not catch it either: Restart Manager asks an application to close by
sending its top-level window a close message, and this is a tray app whose window is hidden. The
message goes nowhere, the wait times out, Setup carries on and DeleteFile fails.

### This one does not depend on the running version

`CloseApplications=force` terminates what does not answer, and `PrepareToInstall` asks the
process to close (`taskkill /IM`), waits, then insists (`taskkill /F /IM`). Asking first means an
app that exits on its own gets to flush its history; one that ignores the request loses at most
the current minute. `AppMutex` stays, so v4.6+ still gets the polite prompt rather than being
terminated.

### I could not test this here

There is no Windows and no Inno Setup compiler in the environment this was written in, so the
installer has never actually been run. This is the second attempt at the same bug.

What was verified instead, against Inno Setup's own source: `force` is a valid value for
`CloseApplications`, the `PrepareToInstall` signature matches theirs exactly, and `Sleep` and
`Exec` are both registered script functions. CI compiling the installer proves the Pascal parses.
None of that proves the behaviour is right.

If it still fails: close LagScope from the tray first. And once this version is installed, the
in-app updater handles later updates by closing the app itself, so this path stops mattering.
