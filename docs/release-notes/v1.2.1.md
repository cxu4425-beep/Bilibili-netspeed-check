## 中文

這一版包含**專案改名**和一個**會影響遊戲延遲準確度的修正**。

### 修正：遊戲會量到錯的伺服器

遊戲和語音程式通常同時開著**一條 UDP 連線到遊戲／語音伺服器**，以及**好幾條 TCP 連線到網站和 CDN**。
原本的排序是「連線數多的優先」，所以會挑到網站那幾條——回報的是「連官網多快」，
而不是「遊戲多卡」。數字看起來正常，但答錯了問題。

現在排序改成 **公網 → UDP → 連線數多**，遊戲伺服器那條永遠優先。另外：

- UDP 位址不再白試 TCP 交握（對 UDP 埠必然失敗，只是白等一個逾時），直接用 ping。
- 伺服器連 ICMP 也擋掉時，會換下一個位址；全都不回應時明說
  「該應用的伺服器不回應偵測（可能封鎖了 ping）」，而不是硬給一個數字。
- 探測錯誤訊息全面在地化，不再把英文句子直接丟到中文介面上。

Roblox（`RobloxPlayerBeta.exe`）就是這個情境的典型例子，已經加進 README 的支援清單。

### 專案改名為 LagScope

原名 Bilibili-netspeed-check / Bilibili Latency Monitor。
名字不再侷限在 B 站，因為它現在能量任何程式的延遲；B 站支援仍然是它最深的部分。

### 改名帶來的變化

| | 舊 | 新 |
| --- | --- | --- |
| 執行檔 | `BiliLatencyMonitor.exe` | `LagScope.exe` |
| 命令列 | `bili-latency` | `lagscope` |
| 設定目錄（Windows）| `%APPDATA%\Bilibili Latency Monitor` | `%APPDATA%\LagScope` |
| 設定目錄（Linux）| `~/.config/bili-latency-monitor` | `~/.config/lagscope` |
| 環境變數 | `BILI_LATENCY_CONFIG_DIR` | `LAGSCOPE_CONFIG_DIR` |

**舊設定會自動搬過來**：第一次啟動新版時，如果新目錄還不存在而舊目錄有東西，
`config.json` 和 `titles.json` 會自動複製過去，房間號、懸浮窗位置、學過的視窗標題都不會丟。
舊目錄不會被刪除，確認沒問題後可以自己清掉。

如果你勾了「開機自動啟動」，路徑指向舊的執行檔——請重新勾一次，指向新的 `LagScope.exe`。

### README

新增「支援哪些 App」一節，列出十個常見的國內外程式和它們的進程名稱
（Discord、Zoom、VALORANT、英雄聯盟、Chrome/Edge、微信、QQ、原神、網易雲音樂、騰訊會議），
並說清楚**沒有白名單**——任何會連網的程式都能量。

## English

This release carries both the **rename** and a **fix that affects how accurate game latency is**.

### Fix: games were measured against the wrong server

A game or voice app holds one UDP socket to the game server and several TCP ones to web and CDN
endpoints. Ranking peers by connection count therefore picked a website and reported its latency
as the game's - a plausible-looking number answering the wrong question.

Peers are now ordered public, then UDP, then busiest. A UDP peer also skips the TCP handshake
entirely (it cannot succeed, and waiting out the timeout only delays the ping that works), and
where a server drops ICMP too the probe moves on and, if nothing answers, says so in the user's
own language instead of leaking an English sentence from the probe.

Roblox (`RobloxPlayerBeta.exe`) is the case that prompted this and is now in the README app list.

### The project is now called LagScope

Previously Bilibili-netspeed-check / Bilibili Latency Monitor. The old name no longer described
it: the tool measures the latency of any application, with Bilibili as its deepest special case
rather than its only subject.

### What the rename changes

| | Old | New |
| --- | --- | --- |
| Executable | `BiliLatencyMonitor.exe` | `LagScope.exe` |
| Command | `bili-latency` | `lagscope` |
| Config (Windows) | `%APPDATA%\Bilibili Latency Monitor` | `%APPDATA%\LagScope` |
| Config (Linux) | `~/.config/bili-latency-monitor` | `~/.config/lagscope` |
| Env var | `BILI_LATENCY_CONFIG_DIR` | `LAGSCOPE_CONFIG_DIR` |

**Existing settings are migrated automatically** on first run: `config.json` and `titles.json`
are copied over, so the room, overlay position and learned window titles all survive. The old
folder is left in place. If you had "start with the system" enabled, re-tick it so it points at
the new executable.

### README

A new "which apps are supported" section lists ten common apps with their process names and
makes the important point explicitly: there is no whitelist - anything that opens a network
connection can be measured.
