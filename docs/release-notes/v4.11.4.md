## 中文

### 📱 `LagScope-viewer.apk`

從這一版開始,每次發布都會一起附上手機版。

它是**電腦上那個儀表板的檢視器**,不是第二個 LagScope——Android 從 10 開始就不讓 App
讀其他程式的連線,所以量測只能在被量的那台機器上做。手機顯示那台機器的數字,即時。

- **沒有帳號,中間也沒有伺服器。** 手機直接連你的電腦,所以桌面版「資料不會離開這台機器」
  的承諾仍然成立。這裡的「登入」就是配對:記住電腦位址和它顯示的存取碼,免得每次重打。
- **權限只有三個**:網路、安裝更新(給自己用的)、以及讀「現在是 Wi-Fi 還是行動網路」。
  **一個都不會跳提示。**
- **自己會更新**:一天查一次,下載後核對 GitHub 發布的 sha256,對不上就刪掉不裝。
- **藍牙延遲校正**也有,量的是那支手機自己的音訊路徑。

> **裝之前先解除安裝任何舊的 LagScope APK。** 這是第一個正式簽章的版本,
> 之前如果你手動裝過測試版,金鑰不同,Android 會拒絕覆蓋。往後就不用了。

### 🔢 版本跟著 release 走

APK 的版本現在由發布標籤決定(`v4.11.4` → `versionName=4.11.4`、`versionCode=41104`)。

這不是為了整齊,是**更新功能的前提**:手機是拿 release 標籤比對 APK 自己的 manifest
來判斷有沒有新版。兩邊各自編號的話(release 4.11.x vs manifest 1.3),那個比較**永遠成立**——
裝了最新版還是會天天說有新版,裝幾次都一樣。CI 現在也會**驗證版本真的蓋上去了**,
沒蓋到就讓建置失敗。

### 🔑 簽章金鑰是在 GitHub 上產的

新增了一個只跑一次的 workflow:金鑰在 GitHub 的 runner 上產生、以 artifact 交付,
**不經過任何聊天視窗、不進 commit、不出現在 log 裡**。密碼也是 runner 自己隨機產的。

它會拒絕覆蓋已經在用的金鑰,除非明確輸入 `regenerate`——換金鑰等於讓每一支裝過的手機
再也無法更新,那不該是點兩下就會發生的事。

## English

**The APK ships from now on.** Every release attaches `LagScope-viewer.apk`
alongside the desktop downloads. The desktop build is identical to 4.11.3.

The viewer is not a second LagScope: Android stopped letting an app read other
apps' connections in 10, so only the machine being measured can do the measuring.
It shows that machine's numbers, live, over your own network - no account, no
server in between. Three permissions, none of which prompt.

**Uninstall any earlier LagScope APK first.** This is the first properly signed
build; a sideloaded test copy would have a different key and Android will refuse
to install over it. Only this once.

**The APK now carries the version of the release it ships in.** The phone compares
the release tag against its own manifest to decide whether an update exists, and
while those were separate schemes that comparison was true forever - an update
offered daily that installing could never satisfy. CI stamps the tag before
building and fails if it did not take.

**The signing key was generated on a GitHub runner** by a one-off workflow and
handed back as an artifact - it never passed through a chat, a commit, or a log.
That workflow refuses to replace a key already in use unless "regenerate" is typed,
because doing so orphans every phone that has the app.
