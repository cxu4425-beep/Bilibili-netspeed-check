> 那不是 MAC 位址——但**會這樣讀完全合理，是格式化錯了**。
>
> A screenshot of 4.11.1 came in asking why the server address looked like a MAC
> address. It was not one - but that reading was entirely fair, and the fault was
> in the formatting.

## 中文

### 🔢 IPv6 位址現在會加方括號

畫面上顯示的是:

```
2607:6bc0::10:443
└──── IPv6 位址 ───┘└埠┘
```

程式碼寫的是 `f"{ip}:{port}"`。對 IPv4 沒問題(`93.184.216.34:443` 一看就懂)，
**但 IPv6 本身就是用冒號分段的**，所以那個字串跟「最後一段剛好是 443 的 IPv6 位址」
無法分辨。標準做法(RFC 3986)是加方括號:

```
[2607:6bc0::10]:443
```

IPv4 維持原樣不變。沒有任何地方會把這個字串反向解析回位址和埠——
唯一的另一個用途是當字典的鍵，那只需要前後一致。

### 📍 監視程式時現在也說得出距離

同一張截圖裡，伺服器那一列**沒有距離上限**——而監視一般程式正是「位址說最少話」的情況，
一個 IPv6 位址完全看不出它在哪。

原因是 `rtt_to_edge` 這個旗標只接在直播那條路徑上，app 和 target 模式漏掉了。
但那兩種模式的往返時間**本來就是量到那台機器的**。資料一直都在，只是被自己的保險擋住。

現在 58 ms 會變成「**至多 5,900 公里**」，而不是什麼都不說。

### 位址不再被距離取代

`locate_line()` 在主機名稱解不出東西時，會把位址整個丟掉、只留距離。
當初的理由是「重複顯示裸主機名沒意義」——但監視程式時**位址就是答案**，
丟掉它等於拿掉唯一能查的東西。現在並排顯示。

### 網站上多了一段實際運作的影片

首頁的「這些是程式真正的畫面」那一節，現在開頭是一段**程式真的在跑**的循環影片：
懸浮窗疊在一場 B 站直播上、監視官方客戶端，數字每兩秒跳一次。

影片裡拿掉了什麼，以及為什麼：

- **彈幕面板整個裁掉**——它有十幾個可辨識的帳號和他們的對話。那是別人的資料，
  不該因為一個講別的事情的網頁而被永久發布。
- **置頂彈幕和捲動的贈禮橫幅模糊化**——兩者都會標出觀眾名字。
- **音軌移除**——自動播放本來就必須靜音，而遊戲配樂也不是我能發布的東西。

畫面裡沒有任何能指認那台電腦的東西：沒有 Windows 帳號名稱、沒有內網位址、沒有視窗標題。

## English

**IPv6 addresses are now bracketed.** `Peer.__str__` was `f"{ip}:{port}"` - fine for
IPv4, but IPv6 is written in colons too, so `2607:6bc0::10:443` cannot be told apart
from an address whose last group happens to be 443. One reader took it for a MAC
address, which was a fair reading. It is now `[2607:6bc0::10]:443` per RFC 3986;
IPv4 is untouched.

**Watching an application can now say how far away the server is.** The `rtt_to_edge`
flag was added for the live path and only wired there, so app and target samples
never carried it - even though their round trip is measured against that very peer.
A 58 ms reply now reads "within 5,900 km" instead of nothing at all, which matters
most precisely here: a bare IPv6 address says nothing about location.

**And the address is no longer replaced by the distance.** When nothing could be
decoded from a hostname, `locate_line()` dropped it and showed only the ceiling.
Watching an application the address *is* the answer, so it now sits beside it.

**The site gained a clip of the app actually running** - the overlay over a live
Bilibili stream. The chat panel is cropped out and the danmaku blurred: both carried
viewers' account names, and none of that belongs on a permanent page about something
else. Audio removed. Nothing identifying the machine is visible.
