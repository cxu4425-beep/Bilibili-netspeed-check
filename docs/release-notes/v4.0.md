## 中文

### ⚡ 自動選最快的 CDN 節點

B 站同一個直播間**同時由好幾個 CDN 節點提供**，播放器拿到哪一個基本是運氣。
差別不小：同一個房間，最快和最慢的節點差幾十毫秒是常事，偶爾差到上百毫秒。

之前的版本只是把這件事**顯示**給你看（診斷資訊裡列出每條線多快）。這一版會**動手**：
每兩分鐘量一次所有節點，發現明顯更快的就換過去。

```
cn-hbyc-ct-01.bilivideo.com   210 ms   ← 播放器給的
cn-gotcha09.bilivideo.com      48 ms   ← 換到這個
```

**它什麼時候才會換**——刻意設得保守，因為換節點要重新連線，不能為了幾毫秒亂跳：

| 條件 | 為什麼 |
| --- | --- |
| 快 **25 ms 以上**，**而且**快 **20% 以上** | 20 ms 差 4 ms 是雜訊；200 ms 差 40 ms 才值得 |
| 距離上次換至少 **3 分鐘** | 兩個速度接近的節點不會來回搶 |
| 目前這個**完全沒回應**時直接換 | 這種情況不用談條件 |
| 只在**格式相同**時比速度 | fmp4 才有伺服器時鐘（實測而非估算），不為了快幾毫秒把精度換掉 |

最後一條是這裡唯一需要想清楚的取捨。fmp4 是唯一帶伺服器時鐘的格式，也就是唯一能讓延遲
是「實測」而不是「估算」的格式。如果為了快 20 ms 換到只有 ts 的節點，數字會變快，
但**準確度會變差**——所以格式永遠排在速度前面，速度只在同格式的節點之間比。

換過的節點會單獨列在體檢報告裡（時間、從哪換到哪、省了多少）：

```
自動換過的線路
  08-29 04:17   cn-slow-01.bilivideo.com → cn-fast-07.bilivideo.com   -162 ms
```

**它改的是什麼**：只影響**這個程式自己**去量哪個節點，**不會**改變你瀏覽器或客戶端
正在播的那一路。也就是說它讓「量到的數字」更接近「這條線最好能到多少」。

不想要就在 **設定 → 高級 → 自動選最快的 CDN 節點** 關掉。

### 其他

- 換節點不會跳通知。它自己在背景發生，跳出來也不用你做什麼，
  該記的地方（報告）記著就好。

## English

### It picks the fastest CDN edge now

Bilibili serves the same live room from several CDN edges, and which one the player gets is
essentially luck. The spread is not small: tens of milliseconds between the best and worst
edge for one room is normal, and occasionally it is over a hundred.

Earlier versions only *showed* you this. This one acts on it: every two minutes it times all
of them and moves to a clearly faster edge.

The bar is deliberately high, because a swap reconnects the stream:

| Rule | Why |
| --- | --- |
| **25 ms** better **and** **20%** better | 4 ms off 20 ms is noise; 40 ms off 200 ms is worth it |
| At most one move every **3 minutes** | two similar edges cannot trade the stream back and forth |
| An edge that stops answering is dropped at once | no haggling needed there |
| Speed only breaks ties **within a format** | fmp4 carries the server clock |

That last rule is the only real trade-off here. fmp4 is the one format that carries a server
date tag, which is what makes the latency *measured* rather than estimated. Moving to an edge
that only offers ts would report a smaller number less accurately - so format stays the
primary key and speed decides only between edges that are equally good on that count.

The report lists the moves it made, with what each one saved. What changes is which edge
**this tool** measures, not which one your browser or the desktop client is playing.

Turn it off in **Settings → Advanced** if you would rather it left the choice alone.

### Also

- A switch raises no notification. It happens on its own, there is nothing for you to do
  about it, and the report is where it belongs.
