## 中文

3.0.0 讓 LagScope 能說出「該怪誰」。這一版讓它能說出「**什麼時候**」——而且能把整件事
交到別人手上。

### 📈 延遲歷史走勢

即時數字只回答「現在怎樣」，隔天早上就沒用了。現在每一分鐘會存下一行摘要，關掉程式也不會丟：

![延遲歷史走勢](https://raw.githubusercontent.com/cxu4425-beep/LagScope/v3.5/docs/images/history.png)

- 藍線是每分鐘的**平均**，淡色帶是那一分鐘的**最好～最差**，
  底部的紅／黃小豎線是**卡頓／延遲突增**發生的時刻。
- **電腦睡著、程式關掉的那段時間，線是斷開的**——不會用一條直線把不存在的資料連起來。
  （上圖中間那段空白就是。）
- 可切 **1 小時／6 小時／24 小時／全部**，下面直接寫出「最不穩定的時段」：
  例如「08-29 01:00　平均 248 ms，最高 710 ms，5 次卡頓或突增」。
- 打開方式：托盤選單 → **延遲歷史…**

**為什麼是每分鐘一行、而不是每一筆樣本**：2 秒一次的話，一天就是 43,200 筆。
存成每分鐘的摘要（均值／最好／最差／P95／抖動／丟失／事件數）之後，一天約 130 KB，
所以可以放心預設保留 48 小時（約 260 KB），開啟視窗也是瞬間畫完。
檔案在設定目錄裡，隨時可以刪；不想記錄就在**設定 → 高級**關掉，即時監測完全不受影響。

### 🧾 一鍵體檢報告

「我家網路很爛」不是一份報告。按下**匯出體檢報告…**，會產生一個 HTML 檔並自動用瀏覽器打開，
裡面有：總覽數字、走勢圖、最不穩定的時段、分段診斷結論、其他監測目標。

- **完全自包含**：圖是內嵌 SVG，樣式是內嵌 CSS，**沒有 JavaScript、沒有任何外部檔案**。
  可以直接當附件寄給客服，離線三週後打開一樣正常，也可以直接列印。
- **可以貼的純文字版**：歷史視窗的「**複製摘要**」把同一份結論複製成純文字，
  適合論壇回覆或聊天室——欄位對齊是按**顯示寬度**算的，中文字不會把表格擠歪。
- **裡面沒有什麼**：不含公網 IP、不含帳號、不含 Cookie、不含你看過的網址。
  出現的位址只有你家內網的（192.168.x.x）和被測的那台伺服器。

### ⌨️ 命令列

```bash
lagscope --report              # 產生報告（順便跑一次分段診斷），印出檔案路徑
lagscope --report ~/net.html   # 指定輸出位置
lagscope --history             # 把最近 24 小時的摘要印成文字
lagscope --history all         # 全部保留的紀錄
```

適合排程：每晚跑一次 `--report`，網路出問題時就有一份現成的證據。

### 其他

- 走勢圖的座標軸改用**整數刻度**（0 / 200 / 400 / 600），不再出現 187.5 ms 這種讀不出來的格線。
- 歷史檔案損壞時會直接忽略、從頭開始記，而不是讓程式啟動失敗。

## English

3.0.0 taught LagScope to say *whose fault* it is. This one teaches it to say *when* — and
to hand the whole thing to somebody else.

### Latency history

One summary row per minute is now kept on disk and survives a restart. The chart draws the
average as a line, each minute's best-to-worst as a band around it, and stalls and spikes as
ticks along the floor. Time the machine spent asleep is a **real gap** in the line, never a
straight segment across data that does not exist. Ranges are 1 h / 6 h / 24 h / everything,
with the roughest hour named underneath. Tray menu → **Latency history…**

A minute-level summary rather than every sample is what makes this affordable: a two second
interval is 43,200 samples a day, while the summaries come to about 130 KB — so two days are
kept by default and the window opens instantly. The file lives in the config folder and can be
deleted at any time; recording can be turned off entirely in **Settings → Advanced** without
affecting live monitoring.

### One-click health report

**Export a health report…** writes a single HTML file and opens it: the chart, the headline
numbers, the roughest hour, the segment verdict, and the side watches. The chart is inline
SVG and the styles are inline — no JavaScript, nothing fetched — so it can be attached to a
support ticket, printed, or opened offline weeks later. **Copy summary** produces the same
findings as plain text for a forum post, padded by display width so CJK labels stay aligned.

It contains latency figures, private addresses inside your own home and the server being
measured. No public IP, no account, no cookies, no browsing history.

### Command line

```bash
lagscope --report              # write the report (runs a path check too) and print the path
lagscope --report ~/net.html   # choose where it goes
lagscope --history             # print the last 24 hours as text
lagscope --history all         # everything still kept
```

### Also

- Chart gridlines are labelled with round numbers instead of quarters of the scale top.
- A damaged history file is ignored and re-started rather than being allowed to fail startup.
