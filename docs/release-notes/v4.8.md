## 中文

### 📊 答案本來藏在錯的地方

v4.7 做了三樣分析:**你被分到哪些節點**、**什麼時候比較卡**、**那我該怎麼辦**。
但它們只寫進了「匯出體檢報告」產生的那個 HTML 檔。

所以實際情況是這樣的:你打開「延遲歷史…」,看到一張走勢圖和幾個數字,
**然後要先匯出一個檔案、再去開它**,才能看到那三個問題的答案。
對一個存在的意義就是回答問題的工具來說,這是把答案放錯了地方。

現在直接在視窗裡:

```
那我該怎麼辦
  1. 重開播放器（或切一次畫質）讓伺服器重新分配節點——你被分到的是 PCDN 節點
       依據: 量到 PCDN 節點
  2. 重開播放器讓伺服器重新分配節點，並確認設定裡的「自動選最快的 CDN」是開著的
       依據: 節點之間差很多
  3. 尖峰時段降一檔畫質，或錯開那幾個小時
       依據: 有時段性

你被分到哪些節點
  節點                                  平均延遲   佔多少時間   卡頓
  upos-sz-mirrorhw.bilivideo.com          67 ms       33%       60
  華為雲 CDN
  cn-hbyc-ct-01.bilivideo.com            160 ms       58%      120
  宜昌 · 中國電信
  xy118x123x45x67xy.mcdn.bilivideo.cn    300 ms        8%        0
  PCDN 邊緣節點（別人家的寬頻）
```

**這裡「該怎麼辦」排在證據前面,跟匯出的報告相反。** 報告是一份文件,證據在前、結論在後讀起來
比較順;這個面板小、要捲動,**開它的人是來找該做什麼的**,把答案放在捲軸下面等於沒放。

**視窗和報告走的是同一個計算。** 不是各算各的——它們呼叫同一個函式,所以你在螢幕上看到的
和你寄給客服的那份,不可能講出不同的話。切換「1 小時 / 6 小時 / 24 小時 / 全部」時分析會跟著重算。

### 為什麼只有這一項

你要我發 v4.8 的時候,程式碼從 v4.7 之後**一行都沒改**——直接發會做出一個跟 v4.7
位元組完全相同、只有版本號不同的東西,而 GitHub **沒有刪除 release 的 API**(v4.4 那次確認過),
撤不回來,還會叫每個裝了的人白白重新下載 44 MB。

所以先去找了有沒有真的該補的東西,找到這一個。

## English

### The answer was in the wrong place

v4.7 added three pieces of analysis - which edges you were given, when it is bad, and what to
try - and put all of them in the exported report only. So opening the history window showed a
chart and some numbers, and finding the answers meant exporting a file and opening that. For a
tool whose whole purpose is answering a question, the answer was in the wrong place.

It is now in the window. **Advice comes before the evidence there, the opposite of the report:
a report is a document and reads better evidence-first, while this panel is small and scrolls,
and someone who opens it came to find out what to do.**

The window and the report go through the same call rather than computing separately, so what
you read on screen cannot say something different from what you send to support. Switching the
range buttons recomputes it.

### Why this is the only change

When this release was asked for, nothing had changed since v4.7 - publishing would have
produced a byte-identical program with a different number, permanently (GitHub has no API to
delete a release) and with a pointless 44 MB update prompt for everyone who has it installed.
So this fixes the real gap instead.
